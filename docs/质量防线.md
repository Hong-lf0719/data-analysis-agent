# 质量防线 · TDD for Skills

> 简历里「99 行校验规则 + 60 项 pytest」的可点击证据。本文说明约束的是什么、由谁执行、怎么复现。

## 为什么要给 LLM 上测试

LLM 生成行为不可预测。这个项目在真实运行中踩过的问题，几乎都不是「代码写错」，而是**模型输出导致的静默失败**：

- 模型反复返回 `clean`，同一低严重度问题被清洗十几次，最后靠 `MAX_STEPS=12` 硬截断，统计和图表一次都没跑；
- 模型返回带 ``` 围栏的 JSON，解析失败直接跳到 report；
- 干净数据被判定「无需分析」，报告里 0 检验 0 图，看起来却跑完了；
- API 超时/限流时异常冒泡，整条链路崩掉，一份报告都拿不到。

所以这里不靠 prompt 祈祷，而是把「模型该干什么」当成可测试契约来治理。

## 三条防线

| 层 | 位置 | 挡住什么 |
|---|---|---|
| 规则层 | `skills/SKILL.md`（99 行） | 定义每个 skill 的输入/输出契约、禁止行为与降级要求，约束 AI 生成代码与分析动作的边界 |
| 代码层 | `agent.py::_decide_action` 线性状态机 | 无论 LLM 返回什么，`clean → stats → viz → report` 每类至少执行一次；LLM 失效退化为确定性推进，杜绝死循环和「0 检验 0 图」 |
| 测试层 | `tests/` 60 项 pytest | 路由终止与循环、编码探测、清洗、统计检验、质量评分、图表落盘、多格式导出、Web 状态持久化、坏文件自动切换，全部可回归 |

另外还有两道运行时护栏：

- **HARD-GATE 数据质量门禁**：`quality_score` 从完整性/唯一性/有效性算 0–100 分；结构性损坏的上传文件（合并表头导致的列错位）会被识别并自动切换到干净数据源，不让脏数据进分析链路。
- **节点级降级**：`analyze` / `clean` / `report` 三个节点的 LLM 调用均有 `try/except`，无 Key、断网、限流时报告仍完整产出，只是不带业务洞察。

## CI

每次 push / PR，GitHub Actions 在 Python 3.10 与 3.11 下执行：

```bash
pytest tests/ -q --cov=tools --cov=agent --cov-report=term-missing
```

Badge 见 [README 顶部](../README.md)。本地复现：

```bash
pip install -r requirements.txt
pip install pytest pytest-cov
pytest tests/ -q        # 60 passed
```

## 已修复的真实缺陷（摘录）

| 现象 | 根因 | 修法 |
|---|---|---|
| 分析卡死、无统计无图 | LLM 决策可反复回到 clean | 代码层强制路由 + 每类步骤至少一次 |
| 报告字段名中文乱码 | 多处裸读 CSV 各自解码，回退到 latin-1 | 统一 `read_df()` 入口，绝不回退 latin-1 |
| 报告只剩 500 字 | `report_node` 误用 `preview` 字段 | 改用完整 `report` 文本 |
| Web 点一下按钮结果全没了 | Streamlit 重跑脚本，widget 状态守门结果区 | 结果区改由 `session_state.analysis_done` 守门 |
| 图表在预览里显示成 `bar bar 图` | `st.markdown()` 不渲染 Markdown 图片 | `_render_report_with_images()` 分段内联 `st.image()` |
| CLI 跑完报告就崩 | `__main__` 块写在 `_interactive_loop` 定义之前 | 入口统一收敛到 `main()`；非交互环境跳过追问 |

> 完整审查记录见仓库根目录 `数据分析Agent-审查与优化文档.md`（七轮修复与验证）。
